# Product Hypothesis & Strategy — NorthBridge One

> [!NOTE]
> Based on secondary research and simulated stakeholder discovery. No real interviews were conducted. This is a portfolio prototype.

## 1. Product Opportunity Statement
Educational institutions lack a unified operational context that helps staff identify, understand and act on student and school-level issues without manually connecting information across disconnected workflows.

## 2. Product Hypothesis
**Hypothesis:** We believe that connecting important educational signals into a unified operational context will help staff identify issues earlier, reduce administrative coordination effort, and enable faster, more informed interventions.

*(Note: This is a hypothesis. It has NOT been validated.)*

## 3. Core Differentiator
**Actionable Student & School Context**
Instead of making users search through different modules (Attendance module, Grading module, Discipline module), NorthBridge One surfaces what requires attention and explains why. The system brings the context to the user, rather than forcing the user to hunt for the context.

## 4. Product Strategy
The platform should help people move seamlessly through a cycle of proactive management:

*   **SEE**: Automatically surface critical signals and anomalies (e.g., "Alex has missed 3 days of Math").
*   **UNDERSTAND**: Provide immediate, holistic context around that signal (e.g., View Alex's Student 360 profile showing recent behavior incidents and parent communications).
*   **DECIDE**: Empower the user with the right information to determine the best course of action.
*   **ACT**: Enable action directly from the context (e.g., Log an intervention, message a parent, assign a task to a counsellor).
*   **FOLLOW UP**: Track the outcome of the action to ensure accountability and close the loop.

## 5. Key Product Decisions

| Decision | Rationale (Because...) |
| :--- | :--- |
| **Decision 1: Build around signals, not modules** | Modules fragment attention. Users shouldn't have to check 5 tabs to see if a student is okay. Signals push relevant context to the user. |
| **Decision 2: Student 360 as the core entity view** | Student context is the most requested information. Every workflow ultimately ties back to a student's wellbeing and progress. |
| **Decision 3: Role-based dashboards focused on decisions** | Different roles need different action items. A Principal needs to see school-wide trends, while a Teacher needs to see their specific class's pending actions. |
| **Decision 4: Structured intervention workflow** | Follow-up accountability is a major gap. Currently, interventions are discussed but poorly tracked. We need a system of record for actions taken. |
| **Decision 5: Explainable signals** | Users must trust and understand the system. If the system flags a student, it must clearly explain *why* (e.g., "Flagged due to: 15% drop in GPA + 4 unexcused absences"). |
